# 记忆系统笔记

> 记录日期：2026-10-22
> 对应实现：`memory.py`（SQLite 存储 + 召回）、`cli.py`（注入与命令）
> 评测脚本：`scratch/memory_eval.py`（gitignore，不随仓库发布）

---

## 一、三层「记得住」

| 概念 | 在本项目里是什么 | 生命周期 |
|---|---|---|
| 上下文窗口 | 一次请求发出去的 `messages` | 一次调用 |
| 会话历史 | `cli.py` 的 `history`、`run_agent` 的 `messages` | 一个进程 / 一个 thread |
| 长期记忆 | `data/memory.db` 的 `memories` 表 | 跨会话，直到被删除 |

`context.compact_observation` 压缩的是第一层；`MAX_TURNS * 2` 截断的是第二层；
`memory.py` 补的是第三层。

**checkpointer ≠ 记忆。** LangGraph 的 `MemorySaver` 存的是图执行状态，为的是断点续跑；
它在内存里、进程重启即丢，而且存的是整段 messages，不是提炼后的事实。
**checkpointer 负责可恢复，memory 负责可回忆。**

---

## 二、设计决策

| 问题 | 决定 | 理由 |
|---|---|---|
| 写什么 | 稳定事实、偏好、项目约束 | 跨会话复用，能改变后续回答 |
| 不写什么 | 一次性指令、敏感信息、模型推断、知识库可查的内容 | 避免污染、泄密与重复 |
| 何时写 | 显式 `记住：…` 优先；隐式留到以后 | 显式可靠；隐式抽取要额外模型调用与阈值 |
| 怎么取 | query 与记忆做 bigram 匹配，排序后取 top-3 | 中文无需分词，成本可控 |
| 怎么忘 | 手动 `/forget` + 记录使用次数 | 先保证能删，再谈自动淘汰 |

一条记忆的价值 ≈ **稳定 × 相关 × 可行动**。三者缺一，它就会占着 top-3 的名额
却挤掉真正相关的记忆。

## 三、实现

### 表结构

```sql
CREATE TABLE memories (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    text         TEXT NOT NULL,
    tags         TEXT NOT NULL DEFAULT '',
    created_at   TEXT NOT NULL,
    last_used_at TEXT,
    use_count    INTEGER NOT NULL DEFAULT 0
);
```

`use_count` / `last_used_at` 现在不参与淘汰，但它们是以后做 TTL、LRU 的唯一依据。
**没有使用记录，就没法回答「哪条该忘」。**

### 召回打分

```python
q = set(tokenize(query))
score = len(q & set(tokenize(memory_text + " " + tags)))
```

排序键是三元组：`(score, use_count, created_at)` 倒序——
先看相关度，再看常用程度，最后看新旧。`top_k` 只是截断，**不是相关度本身**。

### 注入

命中后拼进 **system prompt**，不是 user 消息：

```
已知关于用户的信息（供参考，不要复述）：
- 我的目标岗位是 AI Agent 研发实习
```

放 system 的原因：记忆是背景信息，混进 user 消息会让模型以为
「用户刚刚说了这句话」，回答时就复述出来。

### 命令

| 命令 | 作用 |
|---|---|
| `/mem` | 列出全部记忆与使用次数 |
| `/forget <id>` | 删除一条记忆（只动记忆库，不动会话历史） |
| `/clear` | 清空会话历史（只动 history，不动记忆库） |

「忘掉」要按意图拆开：忘一条事实 → 删记忆；重新开始对话 → 清 history；
忘掉所有个人信息 → 两者都清。

### 冲突处理

prompt 里写明：

> 当用户本轮提供的信息与历史记忆冲突时，以本轮信息为准，不要用旧记忆反驳用户。

但只写 prompt 不够——下一轮旧记忆还在库里，模型又会把它当事实。
系统层面需要在该轮结束时**覆盖或标记旧条目**（`superseded_at`），
否则「以本轮为准」只生效一次。

## 四、评测

### 评测集

6 条种子事实 + 10 条问题，分四类：

| 类型 | 数量 | 目的 |
|---|---|---|
| 直接命中 | 4 | 问题用词与记忆高度重叠 |
| 换词命中 | 2 | 只共享一个关键词，检验召回边界 |
| 干扰项 | 2 | 字面重叠但语义无关（如「AI 芯片」「实习证明」） |
| 无关问题 | 2 | 应当召回为空 |

三个指标：

- **recall@3**：6 条该命中的问题里，正确记忆进入前 3 的比例；
- **误召回率**：4 条不该命中的问题里，返回了任意记忆的比例；
- **平均注入 token**：命中文本字符数 ÷ 2（中文粗略估算）。

评测时把 `memory.DB_PATH` 指向临时库，并把 `memory.touch` 换成空函数——
否则前面几题的召回会抬高 `use_count`，影响后面几题的排序，结果不可重复。

### 两组变量，2×2 对比

| 记忆措辞 | 阈值 | recall@3 | 误召回率 | 平均注入 |
|---|---|---|---|---|
| 原措辞（“我在准备…”） | 1 | 4/6 = 0.67 | 2/4 = 0.50 | 8.0 tokens |
| 原措辞 | 2 | 1/6 = 0.17 | 0/4 = 0.00 | 10.0 tokens |
| 规范措辞（“我的目标岗位是…”） | 1 | **6/6 = 1.00** | 2/4 = 0.50 | 9.2 tokens |
| 规范措辞 | 2 | **4/6 = 0.67** | **0/4 = 0.00** | 9.4 tokens |

### 三个结论

**1. 写入措辞决定召回上限。** 同一套算法、同一批问题，只把记忆改成含问题关键词的表述，
recall 从 0.67 涨到 1.00。算法一行没改。

**2. 阈值是精度与召回的交换，不是优化。** 阈值 1 → 2，误召回 0.50 → 0，
代价是两条换词命中丢失。没有免费午餐。

**3. 提高阈值不等于降低注入成本。** 9.2 → 9.4 tokens 几乎没变：
筛掉的是短记忆，留下的命中反而更长。条数与 token 不是一回事。

### 为什么两条换词用例永远过不去

| 用例 | 与哪条记忆共享 | 交集 |
|---|---|---|
| 我打算找哪类实习？ | JOB | `{实习}` |
| 写代码时你该怎么给我讲？ | STYLE | `{代码}` |
| AI 芯片公司怎么估值？ | JOB | `{ai}` |
| 实习证明怎么开？ | JOB | `{实习}` |

四条的分数都是 1，系统没有语义，无法区分“找实习”和“实习证明”。
**这是关键词匹配的方法论上限，不是阈值能解决的问题。**

## 五、踩坑记录

**评测被自己的副作用污染。** `search()` 会调 `touch()` 更新 `use_count`，
而 `use_count` 是排序第二关键字。评测时必须停掉它，否则用例顺序会影响结果。

**数据库路径不能依赖 cwd。** 用
`Path(__file__).resolve().parents[2] / "data" / "memory.db"`，
和 MCP sandbox 的坑一样：换个工作目录启动就找不到库。

**`data/` 被 Git 跟踪。** 仓库里已有 `data/numbers.txt` 和评测报告，
所以记忆库必须单独加进 `.gitignore`，否则第一次运行就会把个人记忆提交上去。

**注入位置选错。** 拼进 user 消息会让模型把记忆当成“用户刚说的话”。

**只看命中率。** 把所有记忆全量注入的系统命中率也是 100%，但成本与干扰都爆炸。

## 六、已知限制与下一步

- 召回是**字面匹配**，同义改写召回不到（“讲解方式” vs “讲原理”）；
- 没有 TTL、没有自动淘汰，`use_count` 只是为以后留的数据；
- 冲突只靠 prompt 约束，没有把新事实写回或标记旧条目；
- 隐式写入未实现，目前只认 `记住：…` 这类显式表达；
- `memory.py` 还没有单元测试。

下一步优先级：

1. **embedding 召回**：解决同义词与干扰项，这是最大的收益点；
2. **冲突合并**：新事实覆盖旧事实，并保留 `superseded_at`；
3. **单元测试**：去重、排序、沙箱式路径、删除不存在 id。

## 七、面试三分钟版本

> 我给自己的 Agent 加了一套持久记忆：SQLite 存事实，字符 bigram 召回，
> 只把 top-3 拼进 system prompt。用 10 条评测分直接命中、换词、干扰、无关四类，
> 同时看 recall@3 和误召回率——因为只看命中率的话，全量注入也能拿满分。
>
> 两组实验最有价值：把记忆措辞规范化，recall 从 0.67 提到 1.00；
> 把最低重叠数从 1 提到 2，误召回从 0.50 降到 0，但 recall 掉到 0.67。
> 两类错误无法用单一阈值同时解决，根因是字面匹配缺少语义，下一步是 embedding。
>
> 记忆最难的其实不是存，是**决定写什么、什么时候淘汰、冲突时信谁**。
