# RAG 笔记：从「答不出来」到「可溯源地回答」

> 目标：让 Agent 能回答它训练时不可能见过的问题——关于本项目的实现细节、实测数据和踩坑记录。
> 代码：`src/agent_playground/rag.py`；工具入口：`tools.py::search_knowledge`

---

## 一、先证明问题存在（动手前做的实验）

> **本节记录的是「加 RAG 之前」的状态，不要当成当前能力。**
> 同一个问题现在能正确回答：**不做压缩时总输入 2175 tokens**（实测场景：读取一份
> 3203 字符的日志）。保留这段只是为了说明「为什么需要 RAG」。

问 Agent：「我的项目在不做上下文压缩时，单次任务的总输入是多少 token？」

模型的反应：

1. **拒绝凭记忆回答**——「我不能直接凭记忆回答这个数值」。没编，这是对的。
2. **尝试用工具**——调了 `list_files`，发现 `data/` 里只有 `app.log` 和 `numbers.txt`。
3. **承认失败**——「我无法访问你的项目源码。你可以把相关文件放到 `data/` 目录，我再读取分析。」

| 指标 | 数值 |
|---|---|
| 步数 | 2 |
| 输入 / 输出 | 1663 / 206 tokens |
| 成本 | ¥0.00269 |
| 结果 | **没回答出问题** |

注意第 3 步：模型自己提出的替代方案（把文件塞进上下文让我全读），**恰好就是 RAG 要优化的那个做法**。

### 为什么不能真的「全塞」

本项目 6 个文档文件合计 39,711 字符 ≈ 26,474 tokens。

| 做法 | 每次输入 | 成本/次 |
|---|---|---|
| 文档全塞进上下文 | 26,474 tokens | ¥0.02989 |
| 只塞检索出的 top-3 | 518 tokens | **¥0.00065** |

**相差 51 倍（token）/ 46 倍（成本）。** 而这只是 6 个文件；
如果知识库有 100 份同样大小的文档，就是 441,233 tokens——远超上下文窗口，这条路直接断掉。

还有一个更隐蔽的理由：**上下文越长，模型越难找到关键信息**。
塞进去 26,000 tokens 而其中 25,000 是无关内容，噪声本身就会干扰判断。

## 二、实现

### 链路

```
【离线】文档 → 切块 → 向量化 → 建索引          （只做一次）
【在线】提问 → 向量化 → 相似度检索 top-k → 拼进 prompt → 模型作答
```

### 四个关键决策

| 决策 | 选择 | 原因 |
|---|---|---|
| **切块** | 按空行分段，聚合到 300 字，块间留 50 字重叠 | 重叠避免一句话被切在边界上、两块都读不懂 |
| **分词** | 中文按字符 bigram（两个字一组） | 中文没空格，又不引入 jieba 依赖；bigram 是中文检索的常用兜底 |
| **向量** | TF-IDF 稀疏向量 + 余弦相似度 | 当前服务商没有 embedding 接口（实测 404），稀疏向量零依赖可跑通 |
| **top-k** | 3 | 与工具输出长度上限一起权衡，见下文「踩到的坑」 |

### 两个刻意的设计

**1. 向量化独立成方法。** 今天用 TF-IDF 是因为没有 embedding 接口。
把 `_vectorize` 单独拎出来，将来换稠密向量只改这一个方法，其余代码不动。

**2. `fit`（离线）和 `search`（在线）分开。** 建索引读文件、切块、算 IDF，
如果每次调用都重来一遍，就是在反复做已经做完的事。用 `lru_cache` 保证进程内只建一次——
实测第二次检索耗时 **0.000s**（第一次 0.012s），证明这个分工有效。

### prompt 里的幻觉防线

```
【背景资料】[1] … [2] … [3] …
【问题】…
请只依据上面的背景资料回答。如果资料里没有相关信息，直接回答「资料中没有相关信息」，
不要用自己的知识补充。回答时用 [1][2] 这样的编号标注引用了哪段资料。
```

最后那句是整个 RAG 里最便宜也最重要的东西。没有它，模型会把自己的训练知识和检索到的
资料混在一起，而且**分不清哪句来自哪里**。有了它，答案可溯源：
实测回答结尾标注了 `[3]`，翻回去核对，[3] 里确实写着「不做任何压缩时总输入 2175 tokens」。

**编号不是装饰，是让引用可以被检查。**

## 三、三种方式对照实验

同一个问题、同一个模型、同样的 Settings，只改「信息怎么来」：

| 方式 | 输入 | 输出 | 耗时 | 成本 | 含正确数字 | 给出出处 |
|---|---|---|---|---|---|---|
| **A 不检索**（只给问题） | 20 | 593 | 4.68s | ¥0.00258 | ❌ | 无 |
| **B 直接 RAG**（我们检索后塞进 prompt） | 518 | 21 | 1.18s | **¥0.00065** | ✅ | 有 |
| **C Agentic RAG**（Agent 自己决定查不查） | 2647 | 201 | 2.89s | ¥0.00373 | ✅ | 有 |

### 结论 1：RAG 不只是让答案变对，还让答案变便宜

反直觉的地方在这里：**B 的成本只有 A 的 0.25 倍——比不检索还便宜 4 倍。**

原因在成本结构里。输出单价是输入的 4 倍（0.6 vs 0.15 美元/百万 token），
而 A 因为不知道答案，写了 593 个 token 的方法论、建议和「你可以告诉我……我再帮你算」；
B 知道答案，21 个 token 说完。

**输出 token 比输入 token 贵得多，所以「让模型别绕圈子」比「给模型省上下文」更省钱。**
这和上下文压缩那次的结论连上了：那次是输入侧降本（token 降 42%、成本降 28%），
这次是**用输入换输出**——多花 498 个输入 token，省下 572 个输出 token，净赚。

### 结论 2：不检索时，模型的失败方式不是幻觉而是「答非所问」

A 没有编一个数字。它选择给出「如何估算 token 的公式」和一段示例代码——
**看起来很有用，实际上没回答你的问题**。那 593 个输出 token 是纯粹的浪费。

要诚实指出：这次没编，不代表不会编。这取决于当时的提问方式和模型状态。
**不能因为一次没观察到幻觉，就认为幻觉不会发生。** 这也正是需要评测集的原因。

### 结论 3：Agentic 更贵，换来的是自主性

C 相对 A 贵 1.44 倍、相对 B 贵 **5.7 倍**。贵在哪，要说得清：

- **工具 schema 常驻**——6 个工具的 JSON Schema 每轮都要发
- **两次往返**——每次都要重发完整历史
- **回答更完整**——201 vs 21 tokens，它主动补了压缩后的对比和后续建议

换来的是：**Agent 自己决定要不要查、用什么关键词查、要不要换词再查。**
实测它确实这么做了——同一轮里发了两个不同措辞的检索请求：

| 查询词 | 相似度 |
|---|---|
| `上下文成本 优化` | 0.153 |
| `token 成本 压缩` | **0.341** |

同一个意图，换个措辞，相似度差 **2.2 倍**。这是「检索质量由查询措辞主导」的直接证据，
也是 Agentic RAG 的真正价值——**用户口语化的提问天然不适合当检索词，让模型自己改写关键词更有效**。

## 四、踩到的坑

### 坑 1：工具输出被上下文压缩腰斩

检索返回 3 个块 ≈ 898 字符，超过 `compact_observation` 的 800 上限，
被 `compact_head_tail` 丢掉了中间 98 字符。

**这里的关键认识**：`compact_head_tail` 是给「信息在两端」的内容设计的
（文章开头是背景、结尾是结论）。而**检索结果是按相关性排序的列表，信息集中在头部**。
用保守头尾的策略去裁一个排序列表，被切掉的恰好是「次相关」的那一块——最差的一种切法。

修法不是改压缩函数（那是共享的、有测试护着的），而是**让工具自己按优先级装箱**：
上限 780（给下游压缩留余量），按相关性顺序往下放，放不下就停；放不下时明确告诉模型
「只返回了 N/M 条」——**让模型知道自己缺什么，它才有机会换关键词再查一次**。

修完实测三个查询：752 / 793 / 553 字符，全部完整通过，压缩不再改动任何内容。

### 坑 2：类方法返回自身类型会崩

```python
class TfidfIndex:
    def fit(self, chunks: list[str]) -> TfidfIndex:   # ← NameError
```

函数注解在 `def` 语句**执行时**求值，而那一刻类体还没执行完，`TfidfIndex` 这个名字不存在。
模块直接导入失败。正确写法是 `from typing import Self` + `-> Self`。

**ruff 的 F821 不是风格警告，是运行时会崩**——静态检查在这里救了一次。

## 五、已知局限

- **检索用稀疏向量**：同义词匹配不到（搜「报错」找不到写「异常」的段落）。
  服务商没有 embedding 接口，换稠密向量需要另一个 key。
- **块边界按字符数切**：会把不同主题的内容混进同一块。
  实测有一块开头在讲 Observation 截断、后半段才是压缩数据。
- **相似度绝对值低且挤**（0.139 / 0.129 / 0.109），排名区分度弱。
- **没有评测集**：以上所有判断都基于少数几个问题的肉眼观察，
  没有 recall、faithfulness 这类可量化指标。**没评测之前的调参都是猜。**
- `rag.py` 还没有单元测试。
